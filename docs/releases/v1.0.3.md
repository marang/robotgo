# RobotGo v1.0.3

A compatible image-maintenance release of `github.com/marang/robotgo`. It
upgrades `imgo` to 0.44.0 without changing RobotGo's legacy image representation
or filename contracts. Exported signatures, backend selection, agent schemas
and the [v1 runtime support scope](../compatibility/runtime-v1.md) remain
unchanged. The public `Version` constant becomes `v1.0.3`.

## Install

Go 1.26.10 or newer and the documented platform dependencies are required.

```bash
go get github.com/marang/robotgo@v1.0.3
```

## Changes

- Upgrade `imgo` from 0.42.0 to 0.44.0 with a compatibility adapter rather than
  accepting the dependency-only representation change
  ([#178](https://github.com/marang/robotgo/pull/178)).
- Preserve `ToByteImg` and `ToStringImg`: default JPEG quality 70, standard
  Base64, the exact oversized result and trailing NUL bytes, the five existing
  formats, first-format-argument behavior and nil/empty-string failure results.
  The NUL suffix is not extra Base64 `=` padding.
- Preserve `Read` and `Save` case-sensitive last-dot filename interpretation,
  including bare relative format names, quality arguments and error behavior.
  Image decoding benefits from upstream file cleanup and wrapped errors.

## Qualification and limits

Publication requires current-head review and CI, a successful manual Release
evidence run on the final merged source, and an exact-tag run containing six
native/Pure-Go snapshots and all 29 required checks. Verify the public assets
and their commit, tree, ref and run identities using
[Release Evidence v1](../compatibility/release-evidence-v1.md):

```bash
sha256sum -c robotgo-release-evidence-v1.0.3-*.tar.gz.sha256
go list -m -f '{{.Version}}' github.com/marang/robotgo@latest
GOPROXY=direct go list -m -f '{{.Version}}' github.com/marang/robotgo@latest
```

Both module resolutions must report `v1.0.3`; proxies may need to index the
explicit version first. Rollback means pinning `v1.0.2`. Historical tags and
assets remain immutable. Permission-granted macOS runtime evidence remains
externally blocked under [LAB-69](https://linear.app/riotbox/issue/LAB-69);
this release adds no permission or compositor support claims.
