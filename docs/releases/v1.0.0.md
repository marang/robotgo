# RobotGo v1.0.0

RobotGo's first stable release of the independent `github.com/marang/robotgo`
module promotes the reviewed `v1.0.0-rc.2` contract. No runtime implementation,
API signature, agent schema, backend default, or platform support claim changes
from rc.2; the public `Version` constant becomes `v1.0.0`.

## Install and migration

Go 1.26 or newer and the platform's documented native dependencies are required.

```bash
go get github.com/marang/robotgo@v1.0.0
```

```go
import "github.com/marang/robotgo"
```

rc.2 consumers need only change the pinned module version. Consumers upgrading
from rc.1 should also review the
[rc.2 migration guidance](https://github.com/marang/robotgo/blob/v1.0.0-rc.2/docs/releases/v1.0.0-rc.2.md#migration-guidance):
use Go 1.26, validate persisted agent schema versions, and retain deny-by-default
bounded policy for image, accessibility, input, verification, Trace, recorder,
and planning capabilities. Go source compatibility is not a promise of wire
compatibility between independently versioned agent schemas.

## Supported scope and limits

The [Runtime Compatibility Matrix v1](https://github.com/marang/robotgo/blob/v1.0.0/docs/compatibility/runtime-v1.md)
and its [machine-readable contract](https://github.com/marang/robotgo/blob/v1.0.0/docs/compatibility/runtime-v1.json)
define the exact support claim: bounded native and Pure-Go Linux/X11, evidenced
wlroots/Sway and Hyprland behavior, consent-aware GNOME/KDE portal input,
capture and bounds, consent-free macOS contracts, and native plus bounded
Pure-Go Windows behavior. Runtime capability and permission checks still apply.

Permission-granted macOS capture, input and Accessibility remain implemented /
evidence pending under [LAB-69](https://linear.app/riotbox/issue/LAB-69), not
stable-supported. Universal foreign-window control on Wayland core, additional
unevidenced backends, and network/multi-tenant agent security are not claimed.
The MCP adapter remains local stdio. Unsupported operations fail explicitly;
reliability-sensitive callers should prefer strict error-returning APIs.

## Qualification decision and release evidence

The maintainer explicitly requested immediate publication on 2026-10-03 and
waived the project's seven-day RC observation interval. This release does not
claim that seven days elapsed. Only elapsed waiting time is waived: frozen
rc.2 behavior and support scope, no unresolved critical/high defect, current-head
review, complete CI, cleanup/privacy contracts and fresh exact-source evidence
remain mandatory. Existing RC tags and assets remain unchanged.

Publication is accepted only after a new manual evidence run succeeds on the
final merged source and the release event completes exact-tag evidence for
`refs/tags/v1.0.0`. The release must contain both assets:

```text
robotgo-release-evidence-v1.0.0-<commit>.tar.gz
robotgo-release-evidence-v1.0.0-<commit>.tar.gz.sha256
```

Verify the downloaded checksum before extracting:

```bash
sha256sum -c robotgo-release-evidence-v1.0.0-*.tar.gz.sha256
```

Require all six native/Pure-Go platform snapshots, all 29 successful required
checks, and matching annotated-tag commit/tree/ref/run identities. Missing or
mismatched assets, checksums, evidence, or module resolution reject the release.
Verify both default and direct module resolution:

```bash
go list -m -f '{{.Version}}' github.com/marang/robotgo@latest
GOPROXY=direct go list -m -f '{{.Version}}' github.com/marang/robotgo@latest
```

Both must report `v1.0.0`; caching proxies may need to index the explicit version
first. Local upstream-derived tags are not authoritative fork releases.

## Maintenance and rollback

RobotGo maintainers own v1 support and regression triage in the Linear RobotGo
projects. Patch releases prioritize compatible correctness, security and
privacy/cleanup fixes. Public API additions require intentional compatibility
review; breaking Go API changes require a new major module version. Agent
schemas keep their explicit version/migration contracts. Support scope expands
only after exact runtime evidence, never merely because an implementation exists.

Published origin tags and evidence assets must not be moved, deleted or
overwritten. A release-critical regression requires a new version with reviewed
fixes and fresh evidence. To return to the identical pre-stable runtime contract:

```bash
go get github.com/marang/robotgo@v1.0.0-rc.2
```
